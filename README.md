# نظام إدارة عيادة الدكتورة رانية زياد

نظام ويب متكامل لإدارة عيادة الأسنان — واجهة عربية RTL تعمل على iPad واللابتوب.

---

## التشغيل السريع

```bash
npm install
npm start
```

ثم افتح: `http://localhost:3000`

عند أول تشغيل يُنشأ حساب الطبيب تلقائياً وتُطبع بياناته في الطرفية.
**يُطلب تغيير كلمة المرور عند أول دخول.**

لتخصيص بيانات الحساب الأول:

```bash
SEED_DOCTOR_USER=rania SEED_DOCTOR_PASS='كلمة-قوية' npm start
```

---

## متطلبات التشغيل

- **Node.js 22 أو أحدث** (يستخدم وحدة SQLite المدمجة — لا حاجة لتصريف حزم أصلية)
- لا توجد تبعيات نظام أخرى

## إدارة حسابات الطاقم

الطبيب يفتح **الحسابات** ويستطيع:

- إنشاء حساب سكرتيرة: الاسم الكامل، الهاتف، اسم المستخدم، كلمة المرور، الدور
- تعطيل/تفعيل حساب (التعطيل يُنهي جلسات المستخدم فوراً)
- إعادة تعيين كلمة المرور
- حذف حساب (حذف منطقي — البيانات التي أنشأها تبقى)

لا يمكن حذف آخر حساب طبيب نشط، ولا حذف الحساب الذاتي.

---

## بقاء تسجيل الدخول

- الجلسة تُخزَّن في القاعدة بصلاحية **٣٠ يوماً** مع تجديد تلقائي عند كل استخدام
- الكوكي `HttpOnly` + `SameSite=Strict` + `Secure` في الإنتاج
- **تحديث الصفحة أو إغلاق المتصفح لا يُسجّل الخروج**
- الخروج يحدث فقط بالضغط على "تسجيل خروج"، أو عند تعطيل الحساب، أو تغيير كلمة المرور

## الأمان

| التهديد | الإجراء |
|---|---|
| سرقة كلمات المرور | تجزئة scrypt بملح عشوائي ١٦ بايت |
| اختطاف الجلسة | رمز ٢٥٦-بت، يُخزَّن مجزّأً — تسريب القاعدة لا يمنح دخولاً |
| CSRF | رمز مطلوب لكل طلب تعديل، مقارنة بزمن ثابت |
| SQL Injection | استعلامات مُعامَلة حصراً |
| XSS | تهريب كل المخرجات + CSP بدون `unsafe-inline` للسكربت |
| القوة الغاشمة | ١٠ محاولات/١٥ دقيقة لكل IP + قفل الحساب بعد ٥ محاولات |
| تصعيد الصلاحيات | فحص الدور على الخادم لكل مسار |
| Clickjacking | `frame-ancestors 'none'` |

كل عملية حساسة تُسجَّل في `audit_log` مع المستخدم والوقت وعنوان IP.

## الاعتمادية مع آلاف المرضى

- **تقسيم منطقي** لقاعدة البيانات إلى ٦ مجالات
- **فهارس مركّبة وجزئية** على الاستعلامات المتكررة
- **ترقيم إجباري** — لا استعلام يُرجع آلاف الصفوف دفعة واحدة
- **معاملات ذرّية** لكل عملية مالية
- **قيود على مستوى القاعدة**: منع الدفع الزائد، منع الحجز المزدوج، منع تكرار رقم الملف
- **حذف منطقي** — لا تُفقد بيانات
- **WAL mode** للقراءة المتزامنة
- **نسخ احتياطي يومي** تلقائي في `db/backups/`

**قياسات الأداء مع ٥٠٣ مريض:** قائمة المرضى ٥ms، البحث ٣ms، لوحة التحكم ٤ms.

## النشر للإنتاج

```bash
NODE_ENV=production \
SEED_DOCTOR_USER=rania \
SEED_DOCTOR_PASS='كلمة-قوية-جداً' \
PORT=3000 \
npm start
```

في وضع الإنتاج تُفعَّل تلقائياً: كوكي `Secure` (يتطلب HTTPS)، ورأس HSTS، وإخفاء تفاصيل الأخطاء.

**ضع النظام خلف HTTPS** (Nginx أو Caddy). مثال Caddy:

```
clinic.example.com {
    reverse_proxy localhost:3000
}
```

### النسخ الاحتياطي

نسخة تلقائية كل ٢٤ ساعة في `db/backups/`. للنسخ اليدوي:

```bash
cp db/clinic.db "backup-$(date +%F).db"
```

### فحص الصحة

```bash
curl http://localhost:3000/api/health
```

يُرجع حالة الخدمة وسلامة قاعدة البيانات ومدة التشغيل — مناسب للمراقبة الآلية.

## التوسع المستقبلي

- **أكثر من طبيب**: البنية تدعمه — أضف `doctor_id` إلى `appointments` و `visits`، والدور `doctor` موجود أصلاً في `users`
- **PostgreSQL**: المخطط متوافق؛ غيّر طبقة `db.js` فقط
- **تقسيم أفقي**: جدولا `visits` و `payments` قابلان للتقسيم بالسنة عند تجاوز مليون صف
