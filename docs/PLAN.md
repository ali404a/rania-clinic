# خطة المشروع الشاملة — نظام إدارة عيادة الدكتورة رانية زياد

## ١. المعمارية العامة

```
┌────────────────────────────────────────────────────────────┐
│  العميل (iPad / Laptop) — واجهة عربية RTL                  │
│  HTML/CSS/JS  •  ثيم 404 الفاتح  •  أيقونات أسنان مخصصة   │
└───────────────────────────┬────────────────────────────────┘
                            │ HTTPS + Cookie (HttpOnly)
┌───────────────────────────▼────────────────────────────────┐
│  الخادم — Node.js + Express                                │
│  ├─ طبقة الأمان: Helmet, CORS, Rate-limit, CSRF            │
│  ├─ المصادقة: جلسات مخزّنة في القاعدة (بقاء الدخول)        │
│  ├─ الصلاحيات: RBAC (طبيب / سكرتيرة)                        │
│  ├─ التحقق من المدخلات: Zod schemas                         │
│  └─ سجل التدقيق: audit_log لكل عملية حساسة                 │
└───────────────────────────┬────────────────────────────────┘
                            │ SQL معاملات (transactions)
┌───────────────────────────▼────────────────────────────────┐
│  قاعدة البيانات — SQLite (WAL) / PostgreSQL                │
│  مقسّمة منطقياً + فهارس + قيود سلامة + نسخ احتياطي         │
└────────────────────────────────────────────────────────────┘
```

## ٢. تقسيم قاعدة البيانات (لزيادة الاعتمادية مع آلاف المرضى)

### التقسيم المنطقي (Schema Separation)
| المجال | الجداول | سبب الفصل |
|---|---|---|
| **الهوية** | `users`, `sessions`, `audit_log` | أمني — معزول عن بيانات المرضى |
| **المرضى** | `patients`, `patient_medical` | السجل الأساسي، نمو بطيء |
| **الإكلينيكي** | `visits`, `tooth_chart` | نمو سريع (سجل لكل زيارة) |
| **الجدولة** | `appointments` | استعلامات مكثفة بالتاريخ |
| **المالي** | `treatments`, `payments` | تدقيق مالي، معاملات ذرّية |
| **المختبر** | `lab_works` | مستقل |

### استراتيجيات الاعتمادية
1. **فهارس مركّبة** على أعمدة البحث الساخنة (`appointments(date,time)`, `patients(name)`, `payments(treatment_id)`).
2. **الترقيم الصفحي (Pagination)** إجباري — لا استعلام يُرجع كل المرضى دفعة واحدة.
3. **البحث الفوري** عبر فهرس على الاسم + رقم الملف.
4. **المعاملات الذرّية** لكل عملية مالية (تسجيل دفعة = قراءة + تحقق + كتابة + تحديث في معاملة واحدة).
5. **WAL mode** للقراءة المتزامنة دون حجب الكتابة.
6. **الحذف المنطقي** (`deleted_at`) بدل الحذف الفعلي — لا تفقد بيانات أبداً.
7. **نسخ احتياطي** تلقائي يومي + نقطة استعادة.
8. **التقسيم الأفقي المستقبلي**: `visits` و `payments` قابلة للتقسيم بالسنة عند تجاوز مليون صف.

## ٣. الأمان (Security)

| التهديد | الإجراء المضاد |
|---|---|
| سرقة كلمات المرور | تجزئة **scrypt** بملح عشوائي 16 بايت (مقاومة للـGPU) |
| اختطاف الجلسة | كوكي `HttpOnly` + `SameSite=Strict` + `Secure`، معرّف جلسة 256-bit مجزّأ في القاعدة |
| CSRF | رمز CSRF مزدوج التقديم لكل طلب تعديل |
| SQL Injection | استعلامات مُعامَلة (prepared statements) حصراً — لا سلاسل مدمجة |
| XSS | تهريب كل مخرجات المستخدم + `Content-Security-Policy` صارم |
| القوة الغاشمة | حد ٥ محاولات دخول / ١٥ دقيقة لكل IP + قفل الحساب مؤقتاً |
| تصعيد الصلاحيات | فحص الدور على **الخادم** لكل مسار (لا يُعتمد على الواجهة) |
| تسريب البيانات | لا يُرجع الخادم كلمات المرور أو التجزئات أبداً |
| Clickjacking | `X-Frame-Options: DENY` |
| كشف المعلومات | رسائل خطأ عامة للعميل، التفاصيل في السجل فقط |

### بقاء تسجيل الدخول (المطلب الصريح)
- الجلسة تُخزَّن في جدول `sessions` بصلاحية **٣٠ يوماً** مع تجديد تلقائي.
- الكوكي `Max-Age` مطابق — تحديث الصفحة أو إغلاق المتصفح **لا** يُسجّل الخروج.
- الخروج يحدث **فقط** بالضغط على "تسجيل خروج" (يحذف الجلسة من القاعدة).

### إدارة حسابات السكرتيرات (المطلب الصريح)
- الطبيب فقط يملك صلاحية `manage_users`.
- ينشئ الحساب: الاسم الكامل، اسم المستخدم، كلمة المرور، الهاتف، الحالة.
- يمكنه: تعطيل/تفعيل، إعادة تعيين كلمة المرور، حذف منطقي.
- كل عملية تُسجَّل في `audit_log`.

## ٤. معالجة الأخطاء والاعتمادية

- **معالج أخطاء مركزي**: لا يتعطل الخادم من خطأ غير متوقع.
- **التحقق من المدخلات** على كل حقل (Zod) قبل الوصول للقاعدة.
- **قيود على مستوى القاعدة**: `CHECK`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`.
- **منع الحجز المزدوج**: قيد فريد على `(appointment_date, appointment_time)` للمواعيد النشطة.
- **منع الدفع الزائد**: قيد `CHECK` يمنع تجاوز المدفوع للسعر الكلي.
- **فحص الصحة** `/api/health` لمراقبة الخدمة.
- **إيقاف رشيق** (graceful shutdown) عند إعادة التشغيل.

## ٥. خطة الفحص الشامل

1. فحص بنية الشيفرة (syntax + lint).
2. اختبارات وحدة للمنطق المالي والصلاحيات.
3. اختبارات تكامل لكل مسار API.
4. اختبارات أمنية: SQLi, XSS, CSRF, تصعيد صلاحيات, القوة الغاشمة.
5. اختبار حِمل: ٥٠٠٠ مريض + ٢٠٠٠٠ موعد وقياس زمن الاستجابة.
6. فحص سلامة البيانات تحت التزامن (معاملات متوازية).
